# Phase 4 報告：Web GUI

日付: 2026-11-20
状態: **完了（ローカルホスト限定）**。モックモデルの結合テストに加え、STRATA 実機をつないだブラウザ（デスクトップ幅とスマートフォン幅 375×812）で操作を確認した。

## 1. 方式の判断

DeepSeek Harness には独自の Web アプリ（`dsh --profile web`）があり、STRATA にも同梱されている。それを使わず、Hearth デーモンの API の上に軽量なチャット UI を作った。理由は次のとおり。

- DSH の Web アプリは、自分のプロセス内でエージェントのセッションを動かす。そのため、Hearth のタスクキュー、推論リース、タスク単位の予算上限、自動検証の結果、計測値を経由しない。
- STRATA に同梱されている GUI と機能が重なる。
- Hearth の GUI に要るのは「タスク・キュー・検証・リソース」の表示で、データはすべてデーモンの API にある。

UI は依存ゼロ・ビルド不要の HTML / CSS / ES モジュール（`web/`）で、デーモンが配信する。

## 2. 実装内容

| 要件（依頼 §8 Web GUI） | 実装 |
|---|---|
| 会話履歴 | 会話 = 最初のタスクとその `resume` の連鎖（`conversationId`）。サイドバーに一覧を表示し、選ぶと全ターンを再表示する。続けて入力すると、同じ DSH セッションで再開する |
| ファイル添付 | 📎 ボタンかドラッグ＆ドロップ。作業フォルダの `attachments/` に保存し、プロンプトにパスを付ける。ファイル名を無害化（パス成分・予約名・禁止文字を除去）、上限 50 MB（`daemon.maxUploadBytes`） |
| モデル選択・実行モード選択 | 設定済みのモデル・モードを API から取得する。既存の会話ではモデルと作業フォルダを固定し、モードだけ変えられる |
| タスク進捗・ツール実行ログ | NDJSON ストリームでライブ表示。ステップ、ツール呼び出しと結果、思考、ポリシー拒否、JSON 修復、自動検証、バックアップ、スロット待ちを折りたたみ表示する |
| エラー表示 | タスクのエラーを赤枠で表示。セッション切れ・デーモン接続エラーも表示する |
| キュー状態 | 上部に「推論 使用中/上限」「タスク 実行/待機」、設定画面に詳細（3 秒ごとに更新） |
| トークン使用量・生成速度 | タスクごとにステップ数、ツール数、入出力トークン、時間、生成速度（ステップの出力トークン ÷ ステップ時間。プリフィルを含む概算） |
| RAM・GPU 使用率 | CPU（全コアの使用率）、RAM、`nvidia-smi` による GPU 使用率・VRAM・温度 |
| 設定画面 | 既定モード、既定モデル、同時タスク数、同時推論数、削除の扱い、Web 検索、SearXNG URL。`hearth.yaml` のコメントを保ったまま書き込み、完全な設定として読み直して検証してから保存し、実行中のデーモンにも反映する。それ以外（プロバイダ・キー・許可フォルダ）は GUI から変更できない |
| スマートフォン対応 | 760px 以下でサイドバーをドロワーにし、ステータスを折り返し、会話中は固定項目を隠す。ダークモード対応 |
| 外部公開 | 行わない。デーモンはループバック限定のまま |

### セキュリティ

- **ログイン**: `hearth gui` がベアラートークンで 60 秒有効・1 回限りのログインコードを発行し、ブラウザで開く。コードは HttpOnly・SameSite=Strict のセッションクッキー（12 時間）と交換する。デーモントークンは URL に出ない。
- **DNS リバインディング対策**: クッキー認証のリクエストは、Host がこのデーモン（ループバック・同じポート）でなければ拒否する。
- **CSRF 対策**: 変更系のリクエストには `x-hearth-csrf: 1` ヘッダと同一オリジンの Origin が必要。
- ブラウザのセッションからは新しいログインコードを発行できない。
- **XSS 対策**: CSP は `script-src 'self'` でインラインスクリプトを禁止。モデル出力は先にエスケープしてから限定的な Markdown（見出し、リスト、表、コード、太字、http(s) リンク）に変換する。

### STRATA 実機での GUI 操作（内蔵ブラウザ）

1. `hearth gui --no-open` のリンクでログイン → 会話一覧（過去 15 タスク）とステータスを表示。
2. 作業フォルダ `E:\development\hearth-trials\g1` で「scores.csv の平均点と最高点を python_run で計算して表に」を送信。実行中バッジ、推論 1/1、GPU 95% がライブ表示された。18.5 秒で完了し、平均 79.0・最高 Chiba 95 を表として正しく表示した（生成速度 約 32 tok/s）。
3. 同じ会話で「70点未満の人は？」を送信 → 前の文脈を保ったまま「Doi（61点）」と回答（4.1 秒）。
4. スマートフォン幅（375×812）で、ドロワー、会話表示、設定画面（CPU / RAM 94.6/95.7 GB / GPU VRAM 15.3/15.9 GB）を確認した。
5. コンソールエラーなし（CSP 違反なし）。

確認中に見つけて直した表示の不具合: ステータス横と GPU 欄の "null" 表示、検証が無いときの「検証 skipped」表示、スマートフォンで入力欄のプレースホルダが切れる問題、会話中の入力欄が縦に長すぎる問題。

## 4. 未対応・制約

- **リモートアクセス（Tailscale）、ユーザー管理、利用制限は未実装。** 今の設計で拡張できる。デーモンの host 許可リスト、Tailscale ID によるユーザー識別、ユーザーごとのセッションとキュー上限、HTTPS を追加する。外部公開は利用者の承認が必要なので、今回は行っていない。
- **実行中タスクへの承認 UI は無い。** headless 実行の DSH には承認待ちの仕組みが無いため、危険操作は今も拒否される。
- 生成速度はステップ単位の概算（プリフィル時間を含む）。トークン単位のストリーミング表示はしない。DSH headless の `--json` はステップの確定時にテキストを出す。
- 添付は作業フォルダへの保存のみ。画像を画像としてモデルに渡す処理（Vision）は未対応。
- ブラウザでのファイル添付ダイアログ操作は自動テストしていない。アップロード API は結合テストで確認済み。
- 設定画面の「保存」は、利用者の `hearth.yaml` を書き換えるため実機では押していない。同じ処理を結合テストで確認した。
